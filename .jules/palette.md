## 2025-04-21 - Toast Notification Accessibility Pattern
**Learning:** Toast notifications often rely purely on visual cues (colors, unicode icons like `✓` or `✕`) which are problematic for screen readers. Unhandled unicode icons are announced confusingly (e.g., "check mark"), and without an explicit ARIA live region or role, dynamic pop-ups completely fail to alert non-visual users of success or failure states.
**Action:** When creating or reviewing global notification systems (like Toasts), always map the severity type to a dynamic `role` (`alert` vs `status`) and `aria-live` (`assertive` vs `polite`). Additionally, universally hide decorative structural icons using `aria-hidden="true"` and provide explicit `aria-label` alternatives for interactive elements like close buttons.
